# 파일럿 SW-only 스펙 — 1인 창업가 운영 가능 범위

본 스펙은 SafeWay Kids를 **하드웨어 없이 소프트웨어 SaaS만으로 최소 파일럿 운영**하기 위한 축소 범위를 정의한다. v2.0.4 풀 범위(엣지 AI·CCTV·스마트 미러 포함)와 병행 존재하며, 파일럿 단계에서만 본 스펙이 권위를 가진다. V2 전환 시 v2.0.4 범위로 복귀한다.

---

## Phase 0 — Intake

### 1. Requirement Brief

**문제 정의**: 개발이 9개 마일스톤(M0~M9) 완료, 코드 ~18,500 LOC, 규제 샌드박스 신청서 v2.0.4까지 진행된 상태에서, business-operations-manager 평가는 "1인 창업가 전면 런칭 불가, SCALE-DOWN만 가능"으로 결론. 동시에 샌드박스 승인 일정(3~6개월 추가 소요 가능성)이 불확실하여 사업 개시 타이밍을 결정할 법리·운영·재무 기준이 필요.

**원하는 결과**: 다음 3가지를 동시 충족하는 최소 파일럿 실행 설계.
1. **1인 운영 감당 가능**: 24/7 CS 부담, B2B 학원 영업, 기술 인프라 운영이 SDET Code와 병행 가능한 범위
2. **합법성 명확**: 샌드박스 승인 전 운영 가능하거나, 샌드박스 승인 후 즉시 개시 가능한 범위 (Q23 자문 결과에 의해 분기)
3. **V2 확장 경로 보존**: V1 파일럿 후 엣지 AI·하드웨어 추가 시 코드·계약·규제 전환 비용이 최소화되는 구조

**대상 사용자**: 파일럿 범위 기준
- **학원**(B2B, 1~3곳): 서울 1개 구 내 중·고등학생 대상 입시 학원. 기존 셔틀 운영 경험 보유, 원생 총 50명 이하
- **부모**(B2C, 50명 이하): 파일럿 학원 원생의 보호자. 자녀 탑승 상태 실시간 확인 Need 강함
- **기사/동승보호자**(B2B, 2~5명): 학원 계약 전세버스사업자의 기사 + 파일럿 단계에는 동승보호자 배정 선택

### 2. Goals / Non-goals

**Goals**
- G1. 기존 코드베이스의 **엣지 AI 의존 기능**을 격리하여 배포 범위에서 제외
- G2. 파일럿 단계의 **운영 부담을 1인 창업가 주당 30시간 이하**로 제한
- G3. **샌드박스 규제 공백 6개 중 #4(생체정보)를 파일럿 범위에서 제거**하여 리스크 축소
- G4. **OPEX 손익분기 학원 수를 3~4곳**으로 유지 (v2.0.4 범위보다 축소)
- G5. 파일럿 3개월 내 **MRR 150만원 달성 시 V2 확장 재평가**

**Non-goals**
- NG1. 엣지 AI 추론·CCTV·스마트 미러 설치는 본 스펙에서 **제외**(v2.0.4에서 V2로 이관)
- NG2. 안면 임베딩 기반 생체인식 탑승 확인은 **제외**(수동 앱 체크인으로 대체)
- NG3. PetTracker·CareConnect **병렬 런칭은 제외**(SafeWay 파일럿 3개월 결과 후 재평가)
- NG4. 2026년 내 학원 수 5곳 초과 확장 **제외**(1인 운영 한계)
- NG5. 차량 설치 하드웨어 CAPEX를 신청사가 부담하는 모델 **제외**(학원·사업자 부담 또는 V2 연기)

## Phase 3 — Final Tech Spec

### 2.1 사용자 시나리오 (SW-only 범위)

**아침 등원 (예: 07:30)**
1. 기사가 **기사 앱 로그인** → 배차된 원생 명단 확인 (정적 배차, 매일 동일)
2. 각 승차지 도착 → 기사가 **앱 내 "원생 탑승 완료" 수동 체크** + 원생 얼굴 확인은 **기사 육안 + 명단**
3. 부모 앱에 **FCM 푸시 + WebSocket 실시간 위치** → "○○ 탑승 완료, ETA 7분"
4. 학원 도착 → 기사가 **"전원 하차" 체크** → 부모 앱에 도착 알림

**실시간 위치 추적**
- 기사 앱이 5초 주기로 GPS를 백엔드에 송신 → WebSocket으로 부모 앱·학원 대시보드에 브로드캐스트
- 카카오 지도 API로 경로 표시

**이상 상황 (미탑승)**
- 기사가 승차지에서 3분 대기 후 미탑승 체크 → 부모 앱에 즉시 알림
- **자동 전화 기능 없음** (엣지 AI 범위) → 부모가 직접 응답

### 2.3 비기능 요구 사항

- **NFR-1 가용성**: 평일 07:00~20:00 99.5% uptime (피크 외 시간은 99.0%). 1인 운영 한계로 24/7 99.9% 목표 제외
- **NFR-2 실시간 지연**: GPS 위치 업데이트 지연 ≤ 5초, FCM 푸시 발송 지연 ≤ 3초
- **NFR-3 데이터 보호**: 개보법 준수 (기존 준수 범위 유지), **생체정보 처리는 0건** (파일럿 범위)
- **NFR-4 로그**: 기사 수동 체크인 로그는 GPS 좌표·타임스탬프와 함께 감사 로그 저장 (위변조 리스크 대응)
- **NFR-5 부모 커뮤니케이션**: 탑승 알림 오탐지율 ≤ 5% (기사 수동 체크 오류 허용 범위)

    v                          v                         v

    +----------------- PostgreSQL + Redis (세션·큐) -----------------+

    [FCM]   [Kakao Map]   [Toss Payments]

  ✗ [edge_ai/]  ← 비활성 (feature flag)

**핵심 변화**:
- 엣지 AI 디바이스 ↔ 백엔드 간 통신 레이어 **전체 비활성**
- `edge_ai/` 코드는 레포에 유지하되 Docker 이미지에서 제외 (build-time exclusion)
- 모바일 앱 빌드에서 안면 등록 SDK(tensorflow-lite, ML Kit) **의존성 제거**
