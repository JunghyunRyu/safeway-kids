# RIDE vs SafeWay Kids — 장단점 비교 + 규제 공백 차이 분석

> **사용자 핵심 질문 (2026-05-06)**: "RIDE도 규제 샌드박스를 풀었던 건데, 그들이 푼 것을 내가 또 막는? 그런거니까."
>
> **답변 한 줄**: RIDE는 _직영 운송_의 공백을 풀었고, SafeWay는 _N:N 중개_의 공백을 푼다 — **두 공백은 _서로 다른_ 법제 영역**이다. RIDE 통과는 SafeWay에 적용되지 않는다.

---

## 1. TL;DR — 한 페이지 요약

| 항목 | RIDE (㈜스쿨버스) | SafeWay Kids (신청사) |
|---|---|---|
| **승인 상태** | ICT 샌드박스 실증특례 제2023-3-1호 (2023-03 통과, 2년 임시허가 + 최대 4년 연장) | 신규 신청 중 (2026-05-14 제출 예정) |
| **법적 위치** | 여객자동차법 §4 면허 보유 신청기업 (직접 운영) | 여객자동차법 §49의2 제3호 중개업 등록 (매칭 플랫폼) |
| **차량 소유** | 신청기업 직접 구매 + 기사 직접 고용 | 플랫폼 미보유 — 전세버스운송사업자 100% 귀속 |
| **사업 구조** | 1:N (1 회사 ↔ N 학원) 직영 모델 | N:N (N 사업자 ↔ N 학원) 동적 매칭 |
| **AI 거버넌스** | AI 기본법 시행(2026-01-22) **전** 승인 → §31~§34 frame 미적용 | AI 기본법 시행 후 — §33 사전 확인 요청 + §34 ① 책무 자발적 이행 (어린이 통학 첫 행정 선례 목표) |
| **풀어낸 공백** | "신청기업이 차량 직접 보유하는 어린이 통학 영역" | (미해결) "차량 미보유 + N:N 매칭 + 동승보호자 긱 풀 + AI 5축" |

**결론**: 두 사업은 **시장 segment·법제 영역·기술 stack** 모두 다르다. RIDE 선례는 SafeWay에 _**참조**_되지만 _**적용**_되지 않는다.

## 2. 핵심 Reframe — "RIDE 통과 = SafeWay 자동 통과" 함정 차단

### 2.1 잘못된 직관 (질문자가 가질 수 있는 frame)

> "어린이 통학 영역에서 ICT 샌드박스가 한 번 풀렸다 → 같은 영역의 새로운 신청은 중복 → 별도 실증특례 불필요"

### 2.2 실제 구조 (정정된 frame)

ICT 샌드박스 실증특례는 **사업 모델 단위**로 부여되며, 사업 모델이 다르면 **법제 충돌 영역이 다르고 → 풀어야 할 공백이 다르다**. RIDE와 SafeWay는 다음 5축에서 사업 모델이 다르다:

| # | 축 | RIDE 모델 | SafeWay 모델 | 법제 충돌 영역 차이 |
|---|---|---|---|---|
| 1 | **차량 소유 주체** | 신청기업 (단일) | 전세버스사업자 (N) | 자배법 §3 운행자성: RIDE는 단일 / SafeWay는 분담 |
| 2 | **운송계약 구조** | 1:N (1 회사 ↔ N 학원) | N:N (1 사업자가 학원 A·B·C 별개 계약, 사업자 단위 1개 운송계약) | 여객자동차법 §3 + 시행령 §3의2 + 대법원 2008두21294: SafeWay만 새로 풀어야 함 |
| 3 | **동승보호자 운영** | 신청기업 직접 고용 | **긱 풀 + 교육시설 장 전자 지명** | 도교법 §53 ③ "지명" 요건: SafeWay만 새 frame 필요 |
| 4 | **개인정보 처리 주체** | 신청기업 본사 (단일 controller) | 사업자·학원·플랫폼 multi-controller | 개보법 §23 14세 미만 별도 동의 + §28 처리 위탁: SafeWay만 새로 풀어야 함 |
| 5 | **AI 거버넌스** | AI 기본법 시행 전 승인 (2023-03) | AI 기본법 시행 후 (2026-01-22 발효) — §31~§34 적용 | RIDE는 frame 자체 없음 / SafeWay는 §33 사전 확인 신규 |

### 2.3 정보통신융합법 패스트트랙 적용 가능성

2025년 4월 개정 정보통신융합법: **동종·유사** 과제는 관계부처 협의 30일 → 15일 단축. 본 신청사는 위 5축에서 **별도 신규 실증특례**로 신청 적정 — 단, 심사 과정에서 RIDE 선례의 안전 조건·이행 보고 양식을 **참조하여 본 신청사의 조건 이행 가능성을 시연**한다.

## 3. 4-Quadrant 장단점 분석 — 서로의 단점이 서로의 장점

### 3.1 RIDE 장점 (= SafeWay가 못 하는 것)

| # | 장점 | 메커니즘 | SafeWay에서 어려운 이유 |
|---|---|---|---|
| R+1 | **품질 일관성** | 동일 기사·동일 차량 → 어린이 친숙도 ↑ | N:N은 학원당 사업자 변동 가능. 학원 단위 고정 매칭 + AI 5축 mitigation 필요 |
| R+2 | **신뢰 brand 단일화** | 1 회사 brand → 학부모 신뢰 1축 | SafeWay는 사업자 brand + 플랫폼 brand 2축 → 학원 co-branding 필요 |
| R+3 | **Cold start 없음** | 자체 capacity로 시작 | SafeWay는 마포구·용산구 단일 beachhead 집중 + 5/8 게이트 검증 필요 |
| R+4 | **법적 책임 일원화** | 신청기업 단독 자배법 §3 운행자성 | SafeWay는 사업자·학원·플랫폼·동승보호자 4자 분담 → ICT 샌드박스로 명확화 필요 |
| R+5 | **운영 단순성** | 1 회사가 노선·기사·차량·CS 일원 | SafeWay는 VRP-TW 매칭 + 정산 + 3자 CS 복잡 |

### 3.2 RIDE 단점 (= SafeWay가 푸는 것)

| # | 단점 | 어디서 발현 | SafeWay 해결 메커니즘 |
|---|---|---|---|
| R-1 | **자본 비례 확장** | 학원 100곳 = 차량 ~30대 직접 구매 (~15억+) | SafeWay는 0 CapEx — 사업자가 자본 부담 |
| R-2 | **시장 95% 미커버** | 학원이 자체 차량 보유 / 미체계 셔틀 영역 진입 X | SafeWay는 그 영역의 매칭 layer (사업자 ↔ 학원) |
| R-3 | **Network effect 부재** | 직영은 capacity 비례 고용 | SafeWay는 3-sided network (사업자 ↑ → 학원 ↑ → 사업자 ↑↑ loop) |
| R-4 | **지역 확장 비례 CapEx** | 신규 지역 = 차량·기사 신규 채용 | SafeWay는 사업자 1~2곳 등록만으로 capacity 확보 |
| R-5 | **AI 거버넌스 frame 부재** | AI 기본법 시행 전 승인 → §31~§34 미적용 | SafeWay는 §33 사전 확인 + §34 ① 자발적 이행 첫 선례 |
| R-6 | **AI 안전 단축 (1축)** | GPS + 안전운전지수 | SafeWay 5축 (이상행동·잔류·안면·LiDAR·DRT) |
| R-7 | **데이터 누적 속도** | 1 회사 운영 데이터로 한정 | SafeWay는 N×N 매칭·운행·사고 데이터 |

### 3.3 SafeWay 장점 (= RIDE가 못 하는 것)

| # | 장점 | 메커니즘 | RIDE에서 어려운 이유 |
|---|---|---|---|
| S+1 | **자본 효율 unit economics** | 0 CapEx, 한계비용 거의 0 | RIDE 사업 구조상 필연 비례 CapEx |
| S+2 | **3-sided network effect** | 사업자 ↑ → 매칭 가용성 ↑ → 학원 ↑ → 유휴 차량 가동률 ↑ → 사업자 ↑↑ | RIDE는 직영이라 loop 없음 |
| S+3 | **공급 탄력성** | 피크 시간·차량 고장·기사 결근 시 매칭 풀에서 동적 흡수 | RIDE는 capacity 고정 + backup 한계 |
| S+4 | **시장 95% 진입 가능** | 학원 자체 차량 영역 / 미체계 셔틀 영역 모두 매칭으로 흡수 | RIDE 직영은 학원 5%만 커버 |
| S+5 | **AI 5축 깊이** | 이상행동·잔류·안면·LiDAR·DRT 통합 | RIDE는 GPS + 안전운전지수 1~2축 |
| S+6 | **AI 거버넌스 선점** | §33 사전 확인 + §34 ① 자발적 이행 → 어린이 통학 첫 행정 선례 | RIDE는 시행 전 승인이라 frame 자체 없음 |
| S+7 | **데이터 moat** | N×N 매칭·운행·사고 데이터 빠르게 누적 | RIDE는 자체 운영 데이터로 한정 |
| S+8 | **법적 위험 분산** | 자배법 §3 1차 사업자 / 노동법 직고용 X | RIDE는 모든 책임 본사 일원화 (단, 일원화는 단순성 장점이기도 함 — R+4) |

### 3.4 SafeWay 단점 (= RIDE가 이미 푼 것 / 또는 둘 다 어려운 것)

| # | 단점 | 어디서 발현 | SafeWay Mitigation |
|---|---|---|---|
| S-1 | **품질 편차** | 사업자별 차량·기사 매너 차이 | 학원 단위 고정 사업자 우선 매칭 + AI 5축 (사업자 무관 동일 안전 layer) + SLA·검증·평점 |
| S-2 | **Cold start (chicken-and-egg)** | 사업자 부족 → 학원 안 옴 | **마포구·용산구 단일 beachhead** + 5/8 D-7 게이트(가입자 30+/LOI 3+) |
| S-3 | **법적 책임 분담 모호** | 사업자/학원/플랫폼/동승보호자 4자 | (a) 양길모 anchor §3 + Q3 §44의2 (b) **ICT 샌드박스 실증특례 = 책임 분담 명확화의 본질** (c) 운송계약·매칭 약관·보험 3중 |
| S-4 | **신뢰 구축 시간 latency** | 학부모는 낯선 사업자 차량 주저 | 학원 co-branding ("○○학원이 SafeWay로 운행") + 사업자 검증 batch 공개 + 보험·사고 SLA |
| S-5 | **가격 race-to-bottom risk** | 사업자 가격 경쟁 → 안전 투자 ↓ | 안전 SLA 최저선(운임 하한) + 가격 단일 dimension X (검증·평점·안전점수 weighted 매칭) |
| S-6 | **운영 복잡도** | VRP-TW + 정산 + 3자 CS | MVP는 단순 시간창 매칭 (VRP-TW V1.5+) + PortOne v2 정산 reuse + 초기 직접 CS |
| S-7 | **양면 CAC** | 사업자 + 학원 + 학부모 3축 영업·마케팅 | 학원 1곳 = 학부모 50명 + 사업자 1곳 동시 leverage |
| S-8 | **규제 분류 복잡** | §49의2 + §3 + §53 ③ + 자배법 §3 + 개보법 §23 + AI 기본법 §31~§34 동시 충족 | **이게 정확히 ICT 샌드박스 신청의 본질** — 6개 공백 동시 해소 |

## 4. 핵심 — 규제 공백 차이 (왜 별도 실증특례인가)

### 4.1 RIDE가 풀어낸 공백 (제2023-3-1호 범위)

| # | 공백 | RIDE 풀이 방식 |
|---|---|---|
| RG-1 | "신청기업이 차량을 직접 보유하면서 어린이 통학을 운영할 수 있는가" | 신청기업 = 차량 보유자 = 운영자 = 기사 고용주 일원화 모델 승인 |
| RG-2 | "AI 안전 기술(GPS·안전운전지수)을 어린이 통학에 적용 가능한가" | 1~2축 AI 적용 승인 |
| RG-3 | "운영자·기사 안전 의무 + 동승자 의무를 직영 모델에서 어떻게 구현할 것인가" | 직영 모델 안전 조건·이행 보고 양식 확정 |

### 4.2 SafeWay가 풀어야 할 공백 (제2023-3-1호로 풀리지 않은 것)

| # | 공백 영역 | 핵심 조문 | RIDE는 왜 풀리지 않았는가 |
|---|---|---|---|
| SG-1 | **§49의2 제3호 중개업 등록 외연** | 여객자동차법 §49의2 | RIDE는 §4 면허로 직접 운영 — 중개업 등록의 적법 외연 미정의 |
| SG-2 | **§3 전세 정의 / 1개 운송계약 / 사업자 단위 판별** | 여객자동차법 §3 + 시행령 §3의2 + 대법원 2008두21294 + 춘천지법 2016구합51632 | 1대 차량이 학원 A·B·C와 별개 계약 시 "1개 운송계약" 인정 — 1:N 직영 모델은 이 쟁점 미발생 |
| SG-3 | **§53 ③ 동승보호자 지명 / N:N 교차 탑승 / 민사 보수 계약 분리** | 도로교통법 §53 ③ | RIDE는 자체 직고용으로 "지명" 단순. SafeWay는 긱 풀 매칭 + 교육시설 장 전자 지명 신규 frame |
| SG-4 | **개보법 §23 민감정보 (생체 + 14세 미만) 별도 동의 / 처리 / 보관** | 개인정보보호법 §23 + §28 + 안전성 확보조치 §7 | RIDE는 본사 단일 controller. SafeWay는 사업자·학원·플랫폼 multi-controller — 처리 위탁 동의 신규 |
| SG-5 | **AI 기본법 §31·§33·§34 거버넌스 (자발적/의무 이중 트랙)** | AI 기본법 §2 제4호 + §31 + §33 + §34 | RIDE는 AI 기본법 시행(2026-01-22) **전** 승인. SafeWay는 시행 후 첫 행정 선례 목표 |
| SG-6 | **자배법 §3 운행자성 책임 분담 (사업자·학원·플랫폼·동승보호자 4자)** | 자동차손해배상보장법 §3 | RIDE는 신청기업 단독 운행자성 — 분담 쟁점 미발생 |

**핵심**: RIDE 제2023-3-1호는 **6개 공백 중 0개를 풀지 못했다**. RIDE는 _**자기 사업 모델의 공백 (RG-1·2·3)**_을 풀었고, SafeWay는 _**다른 사업 모델의 공백 (SG-1~6)**_을 새로 풀어야 한다.

### 4.3 양길모 변호사 anchor (KISED #32399, 2026-05-02 승인)

법무법인 조율 양길모 변호사 의견서 결론 — RIDE 선례로 풀리지 않는 SG-2·5·6 영역에 대해 신청사 유리한 anchor 확보:

| Q | 영역 | 양길모 결론 |
|---|---|---|
| Q1 | §3 전세 정의 / 1개 운송계약 (SG-2) | **사업자 단위로는 1개 운송계약으로 봄이 타당** (대법원 2008두21294 + 춘천지법 2016구합51632) |

## 5. 시장 Segmentation — RIDE와 SafeWay는 _다른 시장_에 있다

### 5.1 한국 어린이 통학 시장 micro-segmentation

| Segment | 운영 방식 | 시장 점유 (추정) | RIDE | SafeWay |
|---|---|---|---|---|
| A | **학원 자체 차량 보유 + 직고용 기사** | ~60% | ❌ | ⚠️ 매칭 layer로 흡수 가능 (학원이 차량 매각 후 사업자 매칭으로 전환 시) |
| B | **학원 장기 렌탈 + 외주 기사** | ~25% | ❌ | ✅ 매칭 모델 직접 fit |
| C | **학원 미체계 셔틀** (택시·승용차) | ~10% | ❌ | ✅ 매칭 모델 + 안전 layer 도입 |
| D | **전문 운송회사 직영** (RIDE 등) | ~5% | ✅ | ❌ |

**SafeWay 1차 타깃 = Segment B + C (~35%)**, 2차 = Segment A 전환 (~60%) → **시장 95%가 RIDE 미커버 영역**.

### 5.2 두 사업의 공존 시나리오

| 시나리오 | RIDE | SafeWay | 시장 결과 |
|---|---|---|---|
| 직접 충돌 (segment 동일) | Segment D | Segment D | 가능성 LOW — SafeWay는 D 미진입 |
| 인접 보완 (segment 다름) | Segment D | Segment B+C | **현실 시나리오** — RIDE 5% + SafeWay 35% 동시 성장 |
| 후속 확장 (RIDE → 매칭) | RIDE 2.0 | SafeWay V1.5+ | RIDE가 N:N 매칭 pivot 시도 시 → SafeWay는 데이터·네트워크·거버넌스 6~12개월 선점 lock-in |

**결론**: RIDE의 시장 침투는 SafeWay의 시장 침투와 _**거의 겹치지 않는다**_. 두 사업은 **인접 segment에서 보완적으로 성장**하는 구조.
