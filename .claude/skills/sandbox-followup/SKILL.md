# Sandbox Follow-up — 규제 샌드박스 후속 작업 재개 스킬

## 목적

규제 샌드박스 심사 진행 중인 사업체의 후속 미팅·이메일·서류 작업을, 새 세션에서 **0초 컨텍스트 복원**으로 재개한다. 단순 컨텍스트 로딩을 넘어서 **5명의 내장 페르소나로 red team / blue team 품질 게이트**를 강제하여, 모든 회신과 산출물이 다음을 충족하도록 보장한다:

- 사전 공격면 매핑 (앞 3명 페르소나가 예상 질문을 먼저 던진다)
- 사후 품질 검증 (뒤 2명 페르소나가 초안을 점검한다)
- 절대 금기어 자체 검열
- 법조문 번호 인용 강제
- 변호사 검토 필수 지점 🚨 표시

---

## 🎭 내장 페르소나 (5명)

### 앞 페르소나 (Pre-draft) — 질문 예측 / 공격면 매핑

초안을 작성하기 **전에** 실행. "이 답변을 받은 상대방이 어떻게 반응할까"를 3가지 각도에서 예측하여, 답변에 미리 방어선을 포함시킨다.

#### P-A1. 과기정통부 ICT 샌드박스 사무관
**배경**: 10년차 사무관, 절차주의자, 이전 통과 사례 다수 심사 경험
**마인드셋**:
- 신청서 문서와 구두 답변의 정합성을 가장 먼저 본다
- "이전 ㈜스쿨버스 건과 뭐가 같고 뭐가 다른가"를 끊임없이 대조
- 실증특례 부가조건을 사업자가 실제로 이행할 수 있는지 의심

**전형적 질문 패턴**:
- "신청서 §X에는 [내용]이라고 기재되어 있는데, 방금 답변은 조금 다른 것 같습니다. 어느 쪽이 정확합니까?"
- "㈜스쿨버스가 받은 부가조건 중 [조건]을 귀사도 동일하게 준수 가능합니까?"
- "실증 기간 종료 후 본허가 전환을 위한 준비 계획이 있습니까?"
- "파일럿 대상 학원/지역은 어디로 특정할 수 있습니까?"
- "실증 중 사고 발생 시 보고 절차와 책임 분담은 어떻게 설계되어 있습니까?"

**실행 방식**: 현재 답변 초안을 주면, 이 페르소나는 **5개의 후속 질문**을 생성한다. 각 질문은 답변의 가장 약한 지점을 찌른다.

---

#### P-A2. 적대적 운송업 전문 변호사
**배경**: 15년차, 경쟁사(또는 운송사업조합) 자문, 여객자동차운수사업법 해석에 능함
**마인드셋**:
- 귀하의 사업 모델이 **불법**임을 입증하려고 적극적으로 노력
- 대법원 판례와 하급심 판례를 무기로 사용
- "중개"라는 용어 뒤에 숨은 실질을 파고든다

**전형적 질문 패턴**:
- "실질적으로 플랫폼이 차량 배차를 통제한다면, 대법원 판례에 따라 '노선여객자동차운송사업'으로 재분류되어야 하지 않습니까?"
- "N:N 중개라고 하지만, 동일 차량이 매일 같은 학원 학생을 태운다면 자가용 유상운송(§81)과 실질 차이가 뭡니까?"
- "전자계약의 실질이 '기사 포함 차량 임차(타다 유사)'로 해석될 여지는 없습니까?"
- "학원장 명의로 어린이통학버스 신고가 된 차량을 다른 학원 학생이 이용하는 순간, §52 신고 요건 위반 아닙니까?"
- "샌드박스 특례 기간이 끝났을 때, 본허가 없이 계속 운영하면 §81 위반으로 형사 처벌 대상 아닙니까?"

**실행 방식**: 현재 답변 초안을 주면, 이 페르소나는 **"이 사업 모델을 깨뜨릴 법적 논거 3개"**를 생성한다. 각 논거에 대한 반박 준비가 되어 있는지 점검한다.

---

#### P-A3. 학부모 대표 / 아동권익 단체 대변인
**배경**: 학부모 3명의 학부형, 아동권익 시민단체 활동, 안전과 개인정보에 민감
**마인드셋**:
- 기술의 혁신성이 아니라 "내 아이가 위험해지지 않는가"만 본다
- 데이터 유출·해킹 시나리오를 일상적으로 상상
- 사고 시 책임 주체와 보상 범위가 불명확하면 즉시 거부

**전형적 질문 패턴**:
- "안면인식 데이터가 유출되면 우리 아이는 평생 생체정보를 바꿀 수 없습니다. 유출 시 어떻게 책임지십니까?"
- "동의를 거부한 아동은 이 시스템이 적용된 차량을 이용할 수 없습니까?"
- "사고 발생 시 플랫폼-학원-운송사업자-기사 사이에서 학부모는 누구에게 배상을 청구해야 합니까?"
- "AI가 오인식·오작동할 때 백업 인간 점검 체계는 있습니까?"
- "14세 미만 아동의 동의를 법정대리인이 대신 한다면, 아이가 성인이 된 후 본인이 그 동의를 철회할 수 있습니까?"

**실행 방식**: 현재 답변 초안을 주면, 이 페르소나는 **"학부모가 가장 두려워할 시나리오 3개"**를 생성한다. 답변이 그 시나리오에 대한 구체적 대응을 포함하고 있는지 점검한다.

### 뒤 페르소나 (Post-draft) — 출력 검증 / 품질 게이트

초안이 작성된 **후에** 실행. 발송·제출 전 마지막 품질 게이트.

#### P-B1. 정책 심사위원 (100점 채점자)
**배경**: 정부 규제 샌드박스 심의위원회 위원, 공학·법학·정책학 전공자
**채점 5축** (각 20점, 총 100점):

| 축 | 평가 질문 |
|---|---|
| **필요성 (20)** | 현행 규제가 왜 이 사업을 막고 있는가? 현 상태의 사회적 비용은? |
| **혁신성 (20)** | 기존 대안 대비 무엇이 본질적으로 다른가? 단순 개선이 아닌 새로운 접근인가? |
| **시장성 (20)** | 파일럿에서 상용화까지의 경로가 현실적인가? 수요·공급이 실제로 존재하는가? |
| **실현가능성 (20)** | 기술·조직·자금이 실증 기간 내 이행 가능한가? 파트너·인력·자금 확보 상태는? |
| **공익성 (20)** | 개인정보·안전·형평성 등 공익과의 충돌을 얼마나 잘 관리하는가? |

**실행 방식**: 초안을 주면, 이 페르소나는 **5축 각각에 점수를 매기고 감점 사유를 명시**한다. 90점 미만이면 **90점 돌파를 위한 구체적 추가 사항 3개**를 권고한다. 80점 미만은 **재작성 권고**.

**출력 예시**:
```
## 정책 심사위원 채점 결과

필요성: 16/20 (-4 사유: ...)
혁신성: 18/20 (-2 사유: ...)
시장성: 14/20 (-6 사유: ...)
실현가능성: 15/20 (-5 사유: ...)
공익성: 13/20 (-7 사유: ...)
총점: 76/100 — ⚠️ 재작성 권고

90점 돌파 필수 사항:
1. [구체적 항목]
2. [구체적 항목]
3. [구체적 항목]
```

#### P-B2. 컴플라이언스 편집자
**배경**: 대형 로펌 컴플라이언스 팀 출신 에디터, 규제 문서 교열 전문
**검증 항목**:

1. **금기어 자체 검열** (brief §5의 금기어 리스트와 대조)
   - "우리가 소유/보유", "직접 운영/운송", "노선 운행", "기사 고용", "학원끼리 차량 공유"
   - 금기어가 1개라도 발견되면 🚨 **즉시 재작성** 권고

2. **비유 금기어 검열**
   - 타다, 쿠팡플렉스, 배민라이더스, 카카오T 블루 언급 여부
   - 발견 시 🚨 즉시 제거 권고

3. **법조문 인용 형식**
   - 모든 법적 주장에 조·항·호 단위 인용 여부
   - 인용 형식 일관성 (예: "여객자동차운수사업법 제81조")
   - 인용 없는 주장은 ⚠️ 플래그

4. **논리 비약 감지**
   - 전제 → 결론 사이의 누락된 연결고리
   - "~때문에 ~이다" 구조에서 인과 관계가 검증되었는가

5. **오해 소지**
   - 문장이 다른 방향으로 해석될 여지가 있는가
   - 특히 "소유", "운영", "책임"의 주어가 모호한 문장

6. **🚨 변호사 검토 플래그 누락**
   - 구속력 있는 법적 주장에 변호사 검토 권고가 세워져 있는가

**실행 방식**: 초안을 주면, 이 페르소나는 **6개 검증 항목을 순차적으로 점검**한다. 각 항목에 "PASS / WARN / FAIL" 판정. 하나라도 FAIL이면 **발송 금지**, WARN은 사용자 확인 후 발송 가능.

**출력 예시**:
```
## 컴플라이언스 편집자 검증

1. 금기어 자체 검열: PASS
2. 비유 금기어 검열: PASS
3. 법조문 인용 형식: WARN — 2문단에 "§81"이 "제81조"와 혼용됨
4. 논리 비약: PASS
5. 오해 소지: FAIL — "운영합니다"의 주어가 모호. "운송사업자가 운영합니다"로 수정 필요
6. 변호사 검토 플래그: WARN — 안면인식 동의 절차에 🚨 누락

판정: FAIL — 발송 금지, 5번 수정 후 재검증
```

|-----|------|:----------------:|:----------------:|------|
| (없음) | 기본 | ❌ | ❌ | 상태 진단 + 다음 작업 추천 |

| `review` | 페르소나만 | ✅ (3명) | ✅ (2명) | 사용자가 제공한 초안에 대해 5명 페르소나만 실행 |

## 워크플로우

### Step 1 — Brief 자동 발견
`artifacts/business/regulatory/` 디렉토리를 Glob으로 스캔:
- 패턴: `YYYY-MM-DD-*-brief.md` 또는 `YYYY-MM-DD-*-followup-brief.md`
- 가장 최근 날짜 파일을 **active brief**로 선택
- 여러 사업체가 동시 진행 중이면 사용자에게 "어느 사업체인가요?" 확인

### Step 2 — 컨텍스트 로딩
- active brief 전체 읽기
- `memory/MEMORY.md` 인덱스에서 관련 sandbox 메모리(`safeway_sandbox_*.md` 등) 식별 후 읽기
- 신청서 원본 파일 위치 확인 (예: `docs/srs/*신청서*.docx`)
- 관련 법규 리뷰 아티팩트 위치 확인 (`artifacts/reviews/*legal*` 등)

### Step 3 — 상태 진단
다음을 사용자에게 200~400자로 요약:
- 사업체명
- 마지막 통화/미팅 일자와 결과 (잘 된 부분 / 막힌 부분)
- 14일 플랜에서 오늘이 D+며칠인지
- 미해결 이슈(O-1 ~ O-N) 중 가장 시급한 것
- **담당자 이메일 도착 여부를 사용자에게 질문** (아직 안 왔으면 `prep` 모드, 왔으면 `email` 모드 권고)

### Step 4 — Args별 분기

#### 4-A. `(no arg)` 또는 `status`
상태 진단만 수행 후 다음 옵션 중 추천:
- (a) 신청서 .docx 추출 + 답변 정합성 검증
- (b) `korea-regulatory-counsel` agent로 변호사 자문 질문 1차 시뮬레이션
- (c) PIA / exemption-list / roadmap 등 산출물 작성
- (d) 모의 Q&A 리허설

#### 4-B. `email` 모드
**4-B-1. 앞 페르소나 실행 (Pre-draft 공격면 매핑)**
1. 사용자에게 받은 담당자 이메일 본문 요청
2. 이메일 본문 + brief 컨텍스트를 기반으로 앞 페르소나 3명 순차 실행:
   - P-A1 사무관이 던질 후속 질문 5개
   - P-A2 변호사가 던질 법적 논거 3개
   - P-A3 학부모가 던질 시나리오 3개
3. 이 11개의 예상 공격면을 "방어해야 할 지점"으로 사용자에게 제시

**4-B-2. 초안 작성**
1. 질문별로 매칭되는 답변 카드(brief §4의 A~G) 식별
2. 카드 문장을 차용해 회신 초안 작성 (법조문 번호 포함 강제)
3. 앞 페르소나가 찌른 공격면에 대한 선제적 방어 포함
4. 변호사 1차 검토 필수 항목에 🚨 마크

**4-B-3. 뒤 페르소나 실행 (Post-draft 품질 게이트)**
1. 초안을 P-B1 정책 심사위원에게 제출 → 5축 채점 + 감점 사유
2. 점수 90점 미만이면 권고 사항 반영 후 재작성
3. 초안을 P-B2 컴플라이언스 편집자에게 제출 → 6개 항목 검증
4. FAIL 항목이 있으면 발송 금지 + 수정 후 재검증

**4-B-4. 최종본 제시**
1. 회신 메일 통합본 (제목 + 본문, 즉시 발송 가능 형태)
2. 변호사 1차 검토 권고 항목 목록 (있는 경우)
3. 신청서 원본과의 정합성 검증 결과
4. 사용자 발송 승인 요청

#### 4-C. `prep` 모드
1. 오늘 날짜 → 14일 플랜에서 D+N 식별
2. 해당 일자의 작업 항목 추출 (예: D+2~3 PIA 작성, D+6~7 roadmap 등)
3. 산출물 작성 (brief의 산출물 경로 권장에 따라 저장)
4. **뒤 페르소나 2명으로 검증** (P-B1 채점 + P-B2 컴플라이언스)
5. 수정 후 사용자 승인 → 저장

#### 4-D. `review` 모드
사용자가 이미 작성한 초안을 붙여넣을 때 사용. 5명 페르소나만 실행하고 초안 수정은 하지 않음. 리뷰 결과를 사용자에게 돌려주고, 사용자가 직접 수정 후 다시 `review`를 반복할 수 있다.

## 원칙

1. **컨텍스트 재구축 비용을 0으로** — 사용자가 "어제 뭐 했지?" 라고 물을 필요 없게.
2. **페르소나는 항상 5명 모두 실행** (email/review 모드에서) — 게이트를 부분적으로 skip하면 의미가 없다.
3. **답변 카드 그대로 차용** — 즉흥 작문 금지. brief §4의 카드 A~G를 인용.
4. **절대 금기어 자체 검열** — P-B2가 FAIL이면 무조건 발송 금지.
5. **법조문 번호 포함 강제** — 모든 법적 주장에 조·항·호 단위 인용.
6. **변호사 검토 게이트** — 구속력 있는 답변은 🚨 마크 + 자문 권고.
7. **신청서와의 정합성** — 신청서 .docx가 있으면 모든 답변과 정렬 검증.
8. **실행 후 아티팩트화** — 페르소나 리뷰 결과는 `artifacts/business/regulatory/` 하위에 저장하여 다음 세션이 참조할 수 있게.
